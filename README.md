# DiskClearance

**See what goes. Keep what matters.**

DiskClearance is an open-source, safety-first desktop application for understanding and reclaiming storage on macOS. It is designed around explainable findings, review before action, and an honest distinction between moving files to Trash and deleting them permanently.

> **Project status:** pre-release verification. The core scanning, classification, review planning, Trash execution, permanent deletion, duplicate detection, application removal, developer storage rules, and operation history are implemented and covered by automated tests. Released builds remain **unsigned** and not notarized, clean-install verification on earlier macOS releases is not yet performed, and no public release has been tagged yet. In accordance with [SECURITY.md](SECURITY.md), no version is currently supported for production use or trusted with irreplaceable files.

## Platform and distribution constraints

- **Apple Silicon only:** DiskClearance v1.0 is compiled and tested for Apple Silicon (arm64). Intel Macs are **unsupported**.
- **Releases are unsigned:** Released builds are **unsigned and not notarized**. Code signing is planned for v1.0, not implemented. Until it is done, macOS Gatekeeper will refuse to open a downloaded build on a double-click; use **right-click → Open** the first time, or clear the quarantine attribute via `xattr -d com.apple.quarantine <path>`. Nothing here is signed yet and this note stays until something is.
- **Oldest macOS version not yet verified:** The architectural target is macOS 13 Ventura and later. However, verification on macOS 13 and clean-install testing have not yet been performed. The recorded test results and performance measurements were obtained on macOS 26.3 build 25D125.
- **No privileged helper:** DiskClearance ships no elevated daemon and requests no root privileges. Any finding requiring administrator rights to delete is reported with evidence and marked as outside v1.0 scope — never actioned.
- **Windows is unsupported:** The codebase isolates platform-specific logic behind an adapter layer to enable a future Windows port after macOS v1.0 is complete. The current Windows CI build is a compilation check, not verified platform support.

## Performance evidence

Performance figures cited in this project come exclusively from documented benchmarks recorded in [docs/PERFORMANCE.md](docs/PERFORMANCE.md). All measurements were conducted on a single reference host:

- **Host:** Mac mini, Apple M4, 16 GB memory (`sysctl -n machdep.cpu.brand_string` returned `Apple M4`; `system_profiler SPHardwareDataType` reported `Mac mini` and `16 GB`).
- **OS:** macOS 26.3, build 25D125.
- **Scan throughput:** 1,000,000 entries scanned in 21.305769 seconds with peak resident memory remaining flat relative to a 10,000-entry scan (change: -32,768 bytes).
- **Scan latencies:** Time to first verified result was 1.386458 ms at 1,000,000 entries; cancellation request-to-return latency was 0.148041 ms.
- **Duplicate hashing:** 1,073,741,824 bytes streamed in 2.065080 seconds with a maximum read buffer of 65,536 bytes and 9.86 MiB peak resident memory.

These measurements reflect release-mode binary runs on the specified hardware; they do not constitute a performance guarantee on other Mac configurations.

## Safety

DiskClearance handles destructive filesystem operations. Security or data-loss issues should not be filed publicly; follow [SECURITY.md](SECURITY.md). No release should be trusted with real files until the release checklist and destructive-operation test suite pass.

DiskClearance ships no privileged helper and requests no elevated permissions. A finding that would require administrator privileges to remove is shown with evidence and marked as outside v1.0's scope — never actioned. **Unsupported** in v1.0.
